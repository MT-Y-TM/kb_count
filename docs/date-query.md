# 日期查询与反馈

原日期查询用 Chrono 检查格式后，直接把输入字符串交给 SQLite。Chrono 允许未补零的有效日期，例如 `2024-2-29`，而统计行以 `2024-02-29` 保存；原样查询可能返回零。原先格式错误仅显示在页脚，日期输入框和右侧已查询日期也没有解释草稿是否已应用。

现在统计查询、日历和导出范围使用同一日期解析规则：允许首尾空白及未补零的月日，校验真实日历日期及 1—9999 年范围。统计查询始终使用规范 `YYYY-MM-DD`；成功后规范化输入框。无效草稿不进入数据库，也不会改变已显示统计。

日期栏维持原有 44px 高度，按钮位置保持稳定，右侧使用两行反馈：第一行明确“显示”哪一天，第二行显示有效日期提示、尚未查询、可刷新或查询失败信息。新日期尚未查询时强调查询按钮，无效时禁用；输入框回车及直接调用入口仍会重新校验。编辑不触发数据库查询或图表计算。

今日、昨日、日历选择和趋势周期切换共用统计查询入口。昨日以本地日期减一日计算。统计连接的互斥锁正在被占用时，查询使用 `try_lock` 立即给出“统计正在保存，请稍后重试”，避免等锁阻塞事件循环；不声称所有可能耗时的 SQLite 查询均已异步执行。失败提示会保留至编辑、显示日期变化或主动重试，关联当时的日期草稿，避免被 Slint 延后的字段通知抹掉。日期查询入口的小型控制器不改变输入采集、批量写入、数据库结构或便携路径。

## 回归

单元测试覆盖带空格、未补零、闰日、非法日期及年份边界。界面回归使用 Slint 软件窗口与内存 SQLite 的合成聚合行，调用实际查询控制器；没有打开桌面窗口、模拟系统输入或读取个人统计。

- 已有 `2024-02-29` 的 41 次输入，用 ` 2024-2-29 ` 查询必须仍显示 41。
- 输入无效日期时，实际按钮点击与直接调用均不查询；故意持有数据库锁也不能改变该结果。
- 仅编辑日期保留原统计；数据库锁被占用时保留原统计、明确已显示日期并展示忙碌提示，释放后可重试成功。
- 在字段通知尚未执行时调用失败入口，随后渲染，提示仍须保留；更改草稿清除过期错误。
- 今日、昨日、日历与趋势上一／下一周期通过同一真实查询入口；日历接受有空格的有效草稿，拒绝零年。
- 深浅主题覆盖 820×440 最小窗口，以及 100%、125%、150%、175%、200% 缩放下的日期按钮实际点击。
