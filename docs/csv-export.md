# CSV 后台导出

长日期范围的 CSV 原先在 Slint 回调内持有统计数据库的互斥锁，按天查询并写入目标文件。界面会等待整个操作，统计批量保存也可能等待同一把锁；直接创建目标文件还会提前截断已有文件。

现在用户选好保存位置后，按需启动一个导出线程，单独以只读方式打开 EXE 同目录的 `stats.db`。一个日期范围 SELECT 按日期、应用顺序流式读取日汇总，不按无数据的日历天数循环查询，不把全部记录装入内存。导出快照包含读取开始时已经提交的数据；尚在内存聚合或之后提交的输入会在下次导出中出现。

SQLite WAL 允许读快照期间继续写入，单个游标保持一致视图，参见 [SQLite 隔离说明](https://www.sqlite.org/isolation.html)。导出不使用统计写入连接的互斥锁；长导出仍可能延长旧 WAL 页的保留时间，取消或完成后即释放读连接。

一个任务最多使用一个线程、两个容量为 1 的 channel 和 64 KiB 文件缓冲。进度只发送聚合行数，最多每 250 毫秒一次；沿用原有托盘计时器接收进度，不新增空转循环。隐藏或最小化时只清理任务和保留结果，不更新 Slint 属性；恢复后补上结果。没有输入内容、逐次事件或鼠标轨迹日志。

同一时间只能导出一次，日期控件在任务期间禁用，按钮切换为“取消导出”和“取消中…”。仅关闭窗口继续导出；退出应用会发出取消信号，等待线程释放文件和 SQLite 连接，再执行数据库 checkpoint。关闭提醒会说明这一区别，原有记住默认行为的设置继续生效。

输出使用所选目标目录内 `create_new` 创建的唯一临时文件，完成写入、刷新缓冲及文件同步后再同目录重命名替换目标，参见 [Rust rename](https://doc.rust-lang.org/std/fs/fn.rename.html)。取消、查询或保存失败会清理临时文件，原目标保持不变；程序被强制终止时可能留下临时文件。取消在各行及最终替换前检查，正在进行的操作系统磁盘调用返回后才能响应；若替换已经完成，则如实显示导出成功。拒绝将输出选为当前数据库、SQLite 附属文件、同目录配置或正在运行的 EXE。导出目录由用户选择，默认便携路径和数据库结构均未改变。

## 回归方法

存储测试使用新建的独立测试目录和合成统计，不访问个人数据库。覆盖：

- 在读取第一行后同时向 WAL 数据库写入，写入成功且 CSV 的后续行仍来自原快照。
- `0001-01-01` 至 `9999-12-31` 的稀疏日期范围，一次读取已有行。
- CSV 中含逗号的应用路径转义、已有文件成功替换、取消和保存失败后保留原文件、清理临时文件。
- 拒绝覆盖自身数据及 EXE、只读源不存在时不创建空数据库。
- 退出释放任务会发出取消并等待工作线程结束。

Slint 软件窗口使用可控制的测试任务，检查最小窗口 820×440 与 200% 缩放的深浅主题：取消按钮能实际点击、不会再次打开保存窗口、日期固定；隐藏和最小化期间不更新结果，恢复后展示完成行数。它不注册输入设备、不执行系统前台点击，也不导出真实个人统计。

```powershell
$env:KB_COUNT_ASYNC_EXPORT_ONLY = '1'
$env:KB_COUNT_RENDER_UI = '1'
cargo test --locked --offline -- --nocapture
Remove-Item Env:KB_COUNT_ASYNC_EXPORT_ONLY, Env:KB_COUNT_RENDER_UI
```

该开关缩短界面用例，完整回归应清除所有专项开关后执行 `cargo test --locked --offline`。截图为 `target/ui-review/async-export-{minimum,200}-{light,dark}.bmp`；真实 Windows 多屏 DPI、长时间资源占用与极慢磁盘操作仍需要实机测量，不能从离线测试推断性能数值。
