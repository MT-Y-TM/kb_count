# 活动图表与关闭确认

所有查询仍读取 EXE 同目录的 `stats.db`，界面不请求网络。新增 Schema v2 的小时表和原有日表一起在批量事务中写入；迁移也使用事务。小时聚合只保留应用、日期、0–23 小时桶、总量与允许的鼠标分类，不保存按键码、事件顺序或逐次时间戳。日明细继续遵守原有隐私模式。

## 时间与范围

| 选择 | 折线横轴 | 饼图与总量 |
| --- | --- | --- |
| 日 | 本地 24 小时 | 该日完整汇总 |
| 周 | 周一至周日 | 同一自然周汇总，可跨年 |
| 月 | 当月每天，含闰日 | 当月汇总 |
| 年 | 12 个月 | 全年汇总 |

日期栏和日历确定基准日期。年度活动墙使用基准日期所在年，周一为首行，共 365/366 个有效格子；周日开头的部分闰年需要 54 列。月份标签固定在顶部，悬停给出日期与输入总量，点击格子切到当日小时折线。未来且无记录的格子与已过去的零输入区分显示。

折线与占比图的标题右侧共用周期导航：日视图提供“上一日／今日／下一日”，周、月、年依次提供上一周期、本周期、下一周期。周按七天移动，月、年按自然月、自然年移动；月末和闰日按 [Chrono 的日期规则](https://docs.rs/chrono/0.4.44/chrono/struct.NaiveDate.html#method.checked_add_months) 收敛到目标月份的最后一天。返回本周期以当前本地日期为基准。导航同步日期栏、总览、年度墙和当前图表，保留应用筛选、图例开关及折线／占比模式。所有按钮在最小窗口中同排显示，无需手动输入日期。

普通应用和历史应用都可通过名称/路径搜索选择，应用身份仍使用规范化路径。全部应用、单个应用均支持四种周期的折线；六条曲线颜色固定，分别为总输入、键盘、左键、右键、垂直上滚、垂直下滚。总输入还包含中键、侧键与水平滚轮，不是六条曲线相加。图例开关保留到周期切换后，纵轴按可见曲线统一缩放，空白数据不连线。

旧日统计无法推导小时分布：日内图说明未分时数量，周/月/年仍使用完整日统计。Totals Only 保留总量，无法分类的鼠标输入不会被当作分类零次；全范围均无鼠标分类时分类曲线为空并标记“未记录详细数据”，混合范围说明分类仅含已记录部分。Excluded 不新增日表或小时表记录。

## 占比

“输入构成”分为键盘、全部鼠标点击、滚轮绝对单位，三者互不重叠，分母等于当前应用筛选的总输入。“应用占比”使用同一周期的全应用分母；最多七个具名应用，选中应用即使排名低也保留，其余归入“其他”；所选应用该范围无输入时以 0% 图例保留，不绘制虚假扇区。合并不改变分母，Unknown 保留为真实的未知归属。图例提供次数、百分比和名称/路径，滚动图例不会滚动整页。小于 0.1% 的非零占比单独标记；空数据没有虚构扇区。旧日统计可完整用于饼图。

折线和环形图通过 Slint 的内存 SVG 图像接口绘制，几何数据只包含聚合计数及颜色，不包含应用名称或外部资源。Slint 1.13.1 自带软件渲染器的 `draw_path` 未实现，因此使用与正式界面相同的 [Image::load_from_svg_data](https://releases.slint.dev/1.9.0/docs/rust/slint/struct.image#method.load_from_svg_data) 原生图像能力，使离线渲染也能检验实际曲线和扇区；没有引入 WebView 或额外渲染运行时。

窗口逻辑高度低于 500px 时缩短折线绘图区和饼图尺寸。说明文字放在折线上方，使最小窗口滚动到底部后仍可同时看到完整纵轴、横轴、曲线与图例。图例颜色与曲线一致。仅关闭窗口时释放模型持有的图表图像；数据模型仅在打开趋势页、数据版本变化或用户筛选时更新。

## 关闭与退出

主线程使用 `run_event_loop_until_quit`，不会因最后一个窗口隐藏而结束事件循环。点击窗口关闭按钮先显示三种选择，默认键盘焦点在取消：取消保留窗口；仅关闭窗口隐藏面板并保留暂停/运行状态；退出应用与托盘退出使用相同的保存流程。日历、应用选择器及待确认的数据清理会在关闭询问出现时取消。

退出先关闭采集开关，用 [SendMessageTimeoutW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw) 向采集窗口发送同步空消息，等待当前采集回调结束，再请求统计线程最终 Flush。失败、超时或命令队列繁忙均恢复原采集状态、保留进程并提供重试提示；统计线程继续持有未写入批次。成功后隐藏面板、退出 Slint 事件循环、结束统计线程、执行 WAL checkpoint 并移除托盘图标。已提交的 WAL 数据不会因 checkpoint 暂未完成而被丢弃。

最终保存通过零缓冲同步通道确认，只有主线程确实接收成功确认后，统计线程才结束；退出超时或写入失败则继续处理。UI 回调保留的命令发送端不会阻止成功退出后的线程回收。

## 验证方法

普通 `cargo test --locked` 包含数据库、日期桶、隐私策略、迁移、目录复制、退出握手与 Slint 交互回归。测试数据库为内存或 `target/` 下的测试专用文件，不读取个人统计库，也不启动采集。

```powershell
$env:KB_COUNT_RENDER_UI = '1'
$env:KB_COUNT_ACTIVITY_ONLY = '1'
cargo test --locked ui_tests::refresh_preserves_ui_filters_and_privacy_state -- --nocapture
Remove-Item Env:KB_COUNT_RENDER_UI
Remove-Item Env:KB_COUNT_ACTIVITY_ONLY
```

`target/ui-review/` 包含 `activity-{light,dark}-{100,125,150,175,200,minimum}-{annual,trend,mouse,apps}.bmp`、`pie-{light,dark}-{100,125,150,175,200,minimum}-{input,apps,selected}.bmp` 与 `close-{light,dark}-{100,125,150,175,200,minimum}.bmp`。另含仅总量、旧日记录、空饼图和多应用分组预览。

离线回归不代替真实 Windows 多屏 DPI 切换、系统文本缩放、物理输入与资源占用测量。退出按钮的界面测试只记录回调，不终止测试宿主；退出握手另外测试实际 SQLite 提交、失败恢复、队列占满和等待超时。

## 本次验证结果（2026-10-16）

使用 Rust 1.90.0 / Windows MSVC，`cargo fmt --all -- --check`、`cargo check --locked --offline`、`cargo clippy --all-targets --locked --offline -- -D warnings` 全部通过。

完整 `cargo test --locked --offline`：49 项通过、0 失败，62.10 秒。额外活动界面离线绘图回归：1 项通过、0 失败，97.89 秒。覆盖 820×440 逻辑最小窗口、100%/125%/150%/175%/200% 对应客户区及深浅主题，检查日/周/月/年、上一周期／下一周期／本周期的真实组件点击及日期同步、跨年／月底／闰日、全应用/单应用、饼图分母与分组、零输入/旧日记录、图例滚动、关闭三选项及生产主循环的显式退出配置。退出统计线程的同步确认另外覆盖成功接收、接收方超时离开、写入失败三种行为。上述时长为测试运行时间，不代表应用常驻 CPU 或内存指标。
