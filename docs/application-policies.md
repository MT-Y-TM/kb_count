# 应用策略管理

原策略编辑需要完整路径，页面不显示当前有效模式，也没有移除手动覆盖的操作；应用详情进入设置后仍停在偏好设置顶部。较多手动策略还会拼成长段路径文字，查找与管理困难。

设置页现在提供历史应用选择器，搜索名称或路径，支持大小写及正反斜杠；不扫描已安装软件或访问应用文件。选择器复用原有 Slint 应用列表，新增可选标题、筛选按钮及模式说明，趋势选择器保留原有布局和独立筛选状态。策略列表可切换全部、手动策略、已排除；“已排除”包含默认密码管理器策略及手动排除，但列表仅覆盖数据库中已有的应用身份，不代表枚举了全部安装程序。未曾记录的应用仍可手动填写路径添加策略。

选择应用仅填入路径，不保存。编辑区显示当前详细／仅总量／排除模式及默认或手动来源，按钮标识当前模式。点击模式按钮才保存；“恢复默认”删除此路径的手动覆盖，保留应用身份、历史日汇总、小时汇总和明细。默认规则继续使用原有 `CaptureMode::for_application`，没有更改隐私规则或采集线程。策略生效于后续批量聚合；恢复默认不是清空历史。不能据此声称自动过滤全部密码输入。

完整路径不要求当前存在，以便管理迁移后的历史应用；不会解析文件、提权或读取网络位置。空值、空引号、相对路径和目录不能保存，`Unknown` 明确作为无法识别应用的汇总身份保留。规范路径和采集身份一致，不使用 PID 合并历史。未提交路径只查询内存中的策略映射，不逐字访问 SQLite；初始隐藏启动也不加载策略列表。打开设置、重新读取或打开选择器时按需读取，保存成功后更新缓存及详情。锁忙时不等待，读取失败不宣称已确认当前模式，保存失败也不会显示成功。

保存反馈关联当时的路径草稿，Slint 延后的字段通知不会抹掉刚保存的结果；编辑另一条路径会清除过期反馈。主题和启动项反馈改在偏好区域显示，避免与应用策略混在一起。策略列表使用虚拟化 ListView，手动策略总数使用短摘要，避免长段路径挤高设置页面。未增加后台计时器、线程、配置字段、Schema 或数据目录。

详情页进入管理时按策略卡片的实际布局位置滚动，不写死偏好卡片高度。动态设置页首次创建时通过 `init` 报告位置，后续布局变化通过 `changed y` 更新；等待页面切换回调完成滚动重置、卡片位置也已就绪后才定位一次，避免两者到达顺序不同导致滚动被覆盖。本机 Slint 1.13.1 回归覆盖首次创建和缩放。语言语义参见 Slint 官方 [公共回调](https://docs.slint.dev/latest/docs/slint/reference/common/) 与 [属性变化回调](https://docs.slint.dev/latest/docs/slint/reference/language/callbacks/)，实际使用以锁定版本编译、布局与交互验证为准。

## 验证范围

测试使用独立内存 SQLite、合成应用身份和聚合计数，以及 Slint 软件窗口，不注册输入设备、不操作桌面、不读取个人数据库或启动程序。

- 恢复浏览器默认后仍是仅总量，应用身份与此前明细和汇总均保留；恢复不存在的应用不创建新身份。
- 名称／路径搜索、手动与排除筛选，默认排除和手动排除均可查找；选择不会写入策略，也不改变趋势应用筛选。
- 六档尺寸（100%、125%、150%、175%、200%、820×440 最小窗口）、深浅主题中实际点击选择应用、三个模式及恢复默认。
- 持有数据库锁时编辑路径仍可显示缓存模式；非法路径不写库；锁忙时不误报保存成功，重新读取可以恢复。
- 保存后执行延后字段通知，反馈仍在；Escape 可取消选择。
- 详情管理入口直接滚动到编辑区，原有 CSV、清空、日期、趋势和关闭偏好继续完整回归。

```powershell
$env:KB_COUNT_POLICY_ONLY = '1'
$env:KB_COUNT_RENDER_UI = '1'
cargo test --locked --offline ui_tests::refresh_preserves_ui_filters_and_privacy_state -- --exact
Remove-Item Env:KB_COUNT_POLICY_ONLY, Env:KB_COUNT_RENDER_UI
```

专项会提前结束其他界面用例，不能替代清除全部专项开关后的完整测试。预览为 `target/ui-review/policy-{ready,picker,editor}-{缩放}-{light,dark}.bmp`。离线缩放不等同于真实多显示器 DPI 或系统文本缩放实测，Release 长时间 CPU／内存仍需另测。
